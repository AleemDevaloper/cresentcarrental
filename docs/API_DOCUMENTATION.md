# API Documentation

- **Base URL (local):** `http://127.0.0.1:8000/api/v1`
- **Auth:** Sanctum bearer token for `/admin/*` — `Authorization: Bearer <token>`
- **Frontend config:** `VITE_API_BASE_URL` in `frontend/.env` must point at port `8000`.

### Analytics event contract

`POST /analytics/events` accepts:

| Field | Required | Description |
|---|---:|---|
| `event_name` | Yes | `page_view`, `cta_click`, `button_click`, `blog_read` or another validated event name. |
| `session_id` | Yes | Anonymous browser session identifier generated by the frontend. |
| `page_path` | No | Current route and query string. |
| `page_title` | No | Current document title. |
| `target_label` | No | Visible link or button label. |
| `target_href` | No | Link destination when available. |
| `content_type` | No | For example `page` or `blog`. |
| `content_id` | No | Content slug or identifier. |
| `metadata` | No | Additional non-sensitive event context. |
| `referrer` | No | Previous page supplied by the browser. |

The backend adds `user_agent`, `ip_address` and `occurred_at`. Do not send passwords, booking form secrets, payment information, CNIC values or free-form customer notes as analytics metadata.

### Admin analytics response

`GET /admin/analytics` returns:

```json
{
  "data": {
    "stats": {
      "page_views": 0,
      "unique_sessions": 0,
      "cta_clicks": 0,
      "blog_reads": 0
    },
    "top_pages": [],
    "top_actions": [],
    "daily_views": []
  }
}
```

## Conventions

- Admin responses: `data` payload or Laravel paginator (`data`, `links`, `meta`) — the collection manager accepts both.
- Frontend stores the token as `crescent_admin_token` (localStorage when remember, else sessionStorage) and attaches `Authorization: Bearer <token>` via axios interceptor.
- All admin write endpoints should remain protected by authentication, validation, authorization policies and rate limiting in production. Known gap: add role/ability middleware (e.g. `ability:admin`) and global 401 handling for expired tokens.
- Analytics is an operational product signal, not a replacement for consent-managed marketing analytics. Add consent controls before enabling advertising or cross-site tracking in production.
- Vehicle writes update the same `vehicles` records consumed by public `/vehicles` and `/featured-vehicles`; no duplicate frontend fleet catalog exists.
- Booking writes record lifecycle history in `booking_status_history` and admin mutations in `activity_logs`.
